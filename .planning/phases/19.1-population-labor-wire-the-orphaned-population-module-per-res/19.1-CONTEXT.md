<decisions>
## Implementation Decisions

### Per-Residence Population (POP-01)
- `Residence`/`Resident` from `population.ts` (class plebeian/patrician, age bands, employment, children/elderly, taxable income, service access, sentiment, crime/health risk) becomes the live per-house population model, derived from and consistent with the existing level-based population (`HOUSING_LIVE_STATS[level].population` + `effectivePopulation` for merged houses).
- Determinism: resident state derives from tick history (no wall-clock); save/load replay reproduces it byte-identically — no new SaveData fields (replay-derivable or command-derived only).
- The residence inspector (Phase 18) can surface the new per-residence fields (class/age/employment/sentiment) via the read-only `getInspector(kind,id)` seam — no serialized-state growth.

### Migration (POP-02)
- Migration uses an attractiveness index computed from live derived state (desirability, services, unemployment, ratings) with immigration/emigration and homelessness — `netMigration` from population.ts becomes wired.
- Deterministic from state (no wall-clock); immigration/emigration effects are derived deltas, never in getState().

### Labor Sectors (POP-03)
- Labor sectors with priority 1-5, pinning, pause, restore-auto; scarce workers allocated by priority — `allocateWorkers`/`LaborSector` from population.ts wired into the existing worker pool/labor system (workerPool from economy.ts, laborConnected).
- Deterministic allocation; pinned/paused sectors survive save/load via replayable commands or derived state.

### Wage Policy (POP-04)
- Urban wage policy with imperial reference comparison and unemployment band reporting — `wageBand`/`WagePolicy` from population.ts wired into the policy/advisors surface.
- The wage-band report surfaces in the advisors (Phase 18) via a pure projection.

### the agent's Discretion
- Exact wiring points (which existing runner/economy/housing functions consume the new population model).
- How resident fields (age bands, children/elderly, sentiment) are derived deterministically from tick history.
- Migration attractiveness formula inputs and weights.
- Labor priority default order and pinning semantics integration with the existing labor assignment.
- Where the wage-band report surfaces in advisors.

</decisions>

## Existing Code Insights

- `src/sim/population.ts` (104 lines, ORPHANED — imported only by its own unit test): `ResidentClass` ('plebeian'|'patrician'), `Resident`, `Residence` class, `isEligible`, `MigrationInput`/`netMigration`, `SectorPriority` (1-5), `LaborSector`/`allocateWorkers`, `WagePolicy`/`wageBand` — all pure, ready to wire.

- `src/sim/runner.ts`: `getDerived()` (population/employment), `getEmployment()`, `getInspector(kind,id)`/`getWalkerInternals` (read-only seams), house state (level/satisfiedTicks/services/civic).

### Established Patterns
- Deterministic-only sim: no Math.random()/Date.now()/new Date() in sim paths; SimState/getStateJson() byte-identical replay; additive-only API changes; goldens untouched.
- Read-only seams (getInspector/getWalkerInternals) for inspector data — never grow serialized state.
- Replayable SaveCommands for player-action surfaces; derived state from tick history.
- Balance-parity CONFIG.<key> rule (prefer module-local for new constants).

### Integration Points
- `workerPool`/labor system (economy.ts + runner laborConnected) — allocateWorkers by priority.
- Per-house population (runner house state) — per-residence model wired at tick cadence.
- Advisors (Phase 18 composer) — wage-band/unemployment reporting.
- Inspector seam (getInspector) — per-residence fields surfaced in the residence inspector.
