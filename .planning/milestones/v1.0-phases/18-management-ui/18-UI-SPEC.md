# Phase 18 — Management UI Design Contract

> Visual and interaction contract for the Management UI phase (UI-01..UI-04). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Source of truth: `18-CONTEXT.md` (decisions), `openspec/specs/ui-management/spec.md`, `game-specs/game.md` §31–40 (authoritative field lists, Portuguese prose source), existing `index.html` CSS + `src/game/` code (established look).

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — no shadcn. This is a **Phaser 3 + vanilla TypeScript** game with a hand-built DOM overlay (`index.html` inline `<style>`, `HUDScene.buildDom()` via `document.createElement`). An npm component library is **not** applicable (no React/Next/Vite app shell). |
| Preset | not applicable |
| Component library | none — custom DOM (HUD) + Phaser GameObjects (isometric map Graphics/Sprites) |
| Icon library | none — unicode glyphs & text glyphs only (established: `❚❚` pause, `×` close, `◉ ◐ ○ ● ·` food band, `×` speed suffix). No emoji, no icon-font dependency. |
| Font | Georgia, 'Times New Roman', serif (inherits `body` in `index.html`); fallback serif |
| Registry | not applicable (Tool: none) |

**Aesthetic direction (locked):** functional "Roman parchment" theme — dark umber surfaces (`rgba(40,28,14,…)` panels over `#2b1d0e` page), gold (`#e8c46b`) titles/emphasis, bronze borders (`#7a6234`), uppercase micro-labels with letter-spacing. Placeholder/procedural art — **no pixel-perfect fidelity** (CORE decision from `18-CONTEXT.md` "the agent's Discretion": keep styling functional and consistent, no pixel-perfect art). All new panels **must** read as part of this existing system, never as a new design language.

**Constraint — Phase 20 boundary:** this phase wires the functional management UI into the existing right-edge HUD. A full Caesar-III sidebar redesign is **Phase 20 (INSERTED)** and is **out of scope** here. Design decisions in this contract must be implementable without restructuring the layout into the future sidebar.

## Scope Map (UI-01..UI-04)

## Content Hierarchy & Layout

Locked layout decisions (existing + added; arrangement is within the agent's discretion):

| Region | Content | Behavior |
|--------|---------|----------|

Stats panel stays **always-visible** (it is the persistent data strip). |

Tab bar scrolls horizontally when it exceeds drawer width. Default tab: the advisor relevant to the newest critical alert, else Ratings. |
| **New: Overlay toggle bar** (bottom-center, left of/above message log chip area) | 5 overlay buttons (+ "None/clear"), each with keyboard shortcut label | Exactly one overlay active at a time (radio behavior); "None" is the default. Keyboard shortcuts shown in the button label. |
| **Pause/save/restart overlay** (existing) | Paused card: Resume (primary), Save, Restart | Unchanged. Keep `home-btn primary` for Resume. |
| **Toast** (existing `hud-toast`) | Bottom-center transient messages (3s) | Unchanged; feeds from `hud-toast` events. |

**Advisor organization (locked):** tabbed bottom drawer; the always-visible data strip is the existing stats panel (not any advisor). Overlay toggles are a **separate** bar from advisors (they are transient view filters, not advisory content).

**Map view (unchanged):** Phaser isometric view owns the whole canvas; HUD is DOM overlay. Overlay heatmaps are drawn in Phaser on/above the tile layer (below buildings for legibility). Camera pan/zoom/focus is **never** taken over by overlays.

## Inspectors Inventory (UI-04)

Open on click (existing `emitInspect` + `hud-inspect`), rendered in the `hud-popup` card with a title bar (`×` close) and a **Next ◀/▶** controller cycling through entities of the same kind (the "next building" navigation). Field layout per inspector (columns from `game.md` §35–39, minimum viable field set mandated):

### 1. Residence (`residenceInspection` + house state)
- **Header:** level/tier name, residentClass, population/capacity, occupancy, footprint, state/mood.
- **Services:** per-service available/days-remaining list (food, water, labor, health, education, religion, entertainment).
- **Goods:** per-good stock + lack flags.
- **Environment:** desirability, fireRisk, collapseRisk, crime.
- **Evolution:** eligible yes/no + missing requirements list (from housing state; forward-class if cleanly derivable).
- **Controls:** Close/Next only (limit-evolution control is a Phase 19/20 concern).

### 2. Productive building (`productionInspection` + `productionAdvisorRows` row)
- Name, standardized **state** (working / blocked / missing_input / output_full / no_destination / no-road / no-workers / paused / dangerous / burning), workers assigned/required, efficiency, road & labor access, inputs, output, capacity/progress, destination + distance (when present), stop reason (bottleneck string). Standardized states use the **ok/bad color contract** (ok = green, blocked/deficit = salmon).

### 3. Storage — warehouse/granary (`storageInspection`)
- Visual slot representation (rendered grid of slots) + per-product stored/reserved/in-transit/capacity/order rows (`stock`, `usedSlots`/`capacity`).

### 4. Market (`marketInspection` + market config)
- Staff (workers), houses served, internal inventory, demand, supplier/source, buyer/seller activity, enabled products.

### 5. Walker (`walkerInspection`)
- Function/origin/type/state, destination, load, path/steps remaining, distance, services provided, houses served, time-to-return, wait reason.
- Buttons: **Follow** (camera tracks walker), **Route** (draw path as overlay), **Origin** (open origin building inspector).
